# 观隅鸮馆 V3.1.1 接口手册

本软件开发使用了 AI 辅助。

本手册说明 `/api/v1` 下的接口。字段结构的机器可读版本见 [`openapi.json`](../openapi.json)，由 `node scripts/generate-openapi.cjs` 根据源码生成。家族产品使用的只读接口另见[家族对接说明](家族对接说明.md)。

## 1. 通用约定

- **地址**：同源部署为 `https://<你的域名>/api/v1/<路径>`；本机桌面版由软件内部访问，不对外开放。
- **认证**：
  - 浏览器会话：登录后服务端设置 HttpOnly Cookie。修改类请求（POST、PUT、PATCH、DELETE）还须带 `X-Studio-CSRF` 头，值来自登录响应的 `csrf`，并且 `Origin` 必须在 `STUDIO_ORIGINS` 中。
  - 外部集成：在“工作室偏好 → API 密钥与集成”创建密钥，请求时带 `Authorization: Bearer <密钥>`。密钥只拥有创建时勾选的权限点。
- **格式**：请求与响应均为 JSON（`Content-Type: application/json`），单个请求体默认上限 256 KB，各接口另有更小或更大的上限。
- **错误**：返回 `{"error": "说明"}` 与对应状态码。

| 状态码 | 含义 |
| --- | --- |
| 400 | 参数无效 |
| 401 | 未登录或会话已过期 |
| 403 | 没有所需权限，或该接口不接受 API 密钥 |
| 404 | 接口或记录不存在 |
| 405 | 请求方法不支持 |
| 409 | 记录已变化或冲突，请重新读取 |
| 413 | 请求内容过大 |
| 426 | 家族协议版本不兼容 |
| 429 | 请求过于频繁，响应带 `Retry-After` |
| 503 | 依赖组件不可用（例如语音模型未安装） |

- **幂等**：`POST /commands` 可带 `Idempotency-Key` 头（8–120 位字母、数字、`_`、`-`），重复提交返回首次结果。

## 2. 接口一览

### 认证与账户

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `health` | 无 | 服务与版本 |
| GET | `auth/status` | 无 | 是否已创建工作室、开通方式 |
| POST | `auth/bootstrap` | 开通令牌 | 创建首个工作室与超级管理员 |
| POST | `auth/login` | 无 | 登录，返回 `csrf` |
| POST | `auth/register` | 邀请代码 | 成员注册 |
| GET | `auth/me` | 会话 | 当前账户 |
| POST | `auth/logout` | 会话 | 退出并撤销会话 |
| GET / PATCH | `members` | `members:manage` | 成员列表；修改角色或停用 |
| POST | `invitations` | `members:manage` | 生成一次性邀请代码（48 小时有效） |
| GET / POST / PATCH / DELETE | `keys` | `keys:manage` | 列出、创建、复制（须验证密码）、撤销 API 密钥 |
| GET | `audit` | `audit:read` | 最近 200 条审计记录 |
| POST | `password` | 会话 | 修改本人密码 |
| GET / PATCH | `team/profile` | 会话 | 本人网名与真实姓名 |
| GET | `team/members` | `business:read` | 成员目录 |

### 业务数据

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `state` | `business:read` | 读取业务文档；`?revision=n` 未变化时返回 `unchanged` |
| PUT | `state` | 按修改内容 | 提交整份业务文档，须带 `revision` |
| GET | `commands` | `business:read` | 结构化命令目录及参数结构 |
| POST | `commands` | 按命令 | 执行结构化命令 |
| GET / POST | `team/finance` | `finance:read` / 管理者 | 收支流水、分成方案与计算 |
| GET / POST | `retention` | `business:read` / 审批权限 | 留存期限、延期申请与审批、清理 |
| GET | `retention/order-access` | 会话 | 订单资料是否仍可访问（桌面端使用） |
| GET | `weather` | `business:read` | `?latitude=&longitude=&name=` 天气与拍摄提示 |
| GET | `family/capabilities`、`family/orders/<id>` | `business:read` | 家族只读接口 |

`POST /commands` 的请求体为 `{"type": "命令名", "payload": {…}, "revision": n}`。

- **只读命令**（`studio.preferences`、`studio.catalog`、`orders.list`）可以不带 `revision`。
- **写入命令**（其余命令）必须带上当前最新的 `revision`。缺少或不是最新值时返回 409“写入命令需要最新 revision”，避免覆盖他人修改。

推荐流程：

1. 发送一条只读命令（例如 `{"type":"studio.catalog","payload":{}}`），从响应中取得当前 `revision`；带有 `contacts:read` 权限的密钥也可以用 `GET /state`；
2. 带上该 `revision` 提交写入命令，成功后响应中包含新的 `revision`，供下一次写入使用；
3. 收到 409 时重新读取数据，核对变化后再决定是否重新提交。不要不经核对就自动重试。

```bash
curl -s https://studio.example.com/api/v1/commands -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"type":"studio.catalog","payload":{}}'   # 读取 revision
curl -s https://studio.example.com/api/v1/commands -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"type":"orders.update","revision":42,"payload":{"id":"…","location":"城市公园"}}'
```

结构化命令：`studio.preferences`、`studio.configure`、`studio.catalog`、`orders.list`、`orders.create`、`orders.update`、`orders.deliver`、`pre.status`、`post.status`。参数结构以 `GET /commands` 返回为准。

### AI、语音与系统

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET / PUT | `ai/provider` | `ai:configure` | AI 服务配置；密钥只写不读 |
| GET | `ai/status`、`ai/plugins`、`ai/models` | `ai:use` / `ai:configure` | 连接状态、可挂载能力、模型列表 |
| POST | `ai/test` | `ai:configure` | 测试连接，不发送业务数据 |
| POST | `assistant` | `ai:use` | 助手对话；`Accept: text/event-stream` 时以 SSE 流式返回 |
| POST | `assistant/control` | `ai:use` | 中止或调整本人正在进行的回复 |
| GET / POST | `speech` | `ai:use` | 识别状态；提交 16 kHz PCM16（Base64，0.1–30 秒）进行识别 |
| GET | `tts/status` | `ai:use` | 合成状态与音色目录 |
| PUT | `tts/voices` | `ai:configure` | 导入自定义音色清单 |
| POST | `tts/synthesize` | `ai:use` | 合成语音 |
| GET / POST / DELETE | `software/elevation` | 超级管理员 | 临时授予的审批权限 |
| GET | `cli/manual` | 超级管理员会话 | CLI 手册，`?language=en`、`?download=1` |
| POST | `cli` | 超级管理员会话 | 执行或确认 CLI 命令 |
| 各方法 | `hardware/*` | 会话 | 桌面硬件接入 |

## 3. 示例

将 `studio.example.com` 和 `<密钥>` 换成实际值。

```sh
# 查询订单
curl -fsS https://studio.example.com/api/v1/commands \
  -H "Authorization: Bearer <密钥>" \
  -H "Content-Type: application/json" \
  -d '{"type":"orders.list","payload":{"query":""}}'

# 读取家族订单引用
curl -fsS https://studio.example.com/api/v1/family/orders/<订单编号> \
  -H "Authorization: Bearer <密钥>" \
  -H "X-Limet-Family-Protocol: 1"
```

## 4. 注意事项

- API 密钥不能访问 CLI、留存的桌面接口和 AI 服务配置。
- 接口返回的金额为工作室币种，不随界面语言变化。
- 接口可能随版本调整，接入前用 `GET /health` 核对版本。
