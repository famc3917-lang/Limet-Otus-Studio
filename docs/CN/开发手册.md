# 观隅鸮馆 V3.1.1 开发手册

本软件开发使用了 AI 辅助。

本手册面向有 Node.js、TypeScript 与 React 基础的第三方开发者，说明源码的结构、数据与权限模型、桌面端、语音组件、测试与构建方式。操作说明见[使用手册](使用手册.md)，服务器部署见[部署手册](部署手册.md)，接口见[接口手册](接口手册.md)。

软件按现状提供，不保证数据完整、服务持续可用或金额计算准确，见[现状与责任说明](../../NOTICE-AS-IS.md)。

## 1. 环境

| 项目 | 要求 |
| --- | --- |
| Node.js | 24（使用内置 `node:sqlite`） |
| 包管理 | npm，按 `package-lock.json` 安装 |
| 桌面构建 | Windows x64，Electron 44，electron-builder 26（便携版）；安装版由 `installer/`（WPF，.NET Framework 4.8，Windows 自带编译器）生成 |
| 可选数据库 | PostgreSQL；未设置 `DATABASE_URL` 时使用 SQLite |

```sh
npm ci
cp .env.example .env    # 按需填写，见第 4 节
npm run dev             # Next 开发服务器，默认 http://localhost:3000
```

首次进行桌面构建前，执行 `node node_modules/electron/install.js` 下载 Electron 运行时（发布脚本缺少时会自动执行）。npm 提示部分依赖的安装脚本未获允许时，可保持默认，不影响构建。

Next.js 版本为 16，构建使用 `next build --webpack`。该版本的部分约定与旧版不同，修改路由或配置前请查阅 `node_modules/next/dist/docs/`。

| `src/components/biz/` | 业务组件：工作台、表单、对话框、助手、设置、打印编辑器等 |

| `electron/` | 桌面主进程与各功能宿主（窗口、助手悬浮球、语音合成、语音识别、草稿、硬件、媒体权限） |
| `speech/` | 语音识别 worker、npm 运行时清单、模型清单 `MODEL.json` |

| `scripts/` | 构建、清单生成、发布、源码导出与审计 |

| `third-party/` | 随安装包分发的第三方许可与声明 |

## 3. 架构

### 3.1 运行形态

- **同源模式**：Next 服务同时提供页面和 `/api/v1/*`。桌面版与本机开发使用这种方式。
- **独立 API 模式**：`npm run build:api` 用 esbuild 把 `src/server/main.ts` 打包为 `dist-api/server.cjs`，独立监听 `STUDIO_API_HOST:STUDIO_API_PORT`（默认 `127.0.0.1:38322`）。前端构建时设置 `NEXT_PUBLIC_API_BASE_URL` 指向它。容器部署模板使用这种方式。

两种形态共用 `src/server/http.ts` 中的 `handleAPI`。

### 3.2 桌面端

`electron/main.cjs` 启动本地 Next standalone 服务，并把数据目录、语音资源目录等通过环境变量传给它。窗口使用无边框样式，界面内的红、黄、绿按钮通过 `window-host.cjs` 的 IPC 控制窗口。各宿主只接受来自主窗口、且来源与本地服务一致的调用。

| 文件 | 职责 |
| --- | --- |
| `window-host.cjs` | 最小化、最大化、关闭；窗口底色随主题同步并记入 `userData/window-theme.json` |
| `assistant-host.cjs` | 桌面悬浮球、托盘、后台运行、全局快捷键 Ctrl+Alt+Space、界面语言偏好 |
| `tts-host.cjs` | 软件内安装语音合成运行时与模型 |
| `speech-host.cjs` | 软件内安装语音识别模型 |
| `drafts-host.cjs` | 未保存草稿的加密暂存 |
| `hardware-host.cjs`、`media-host.cjs` | 可移动存储检测；麦克风权限只授予主窗口音频 |
| `security.cjs` | 原生调用的会话与权限校验 |
| `preload.cjs` | 暴露给页面的受限桥接 `window.desktop` |

### 3.3 业务数据

每个工作空间的业务数据（订单、前后期工单、客户类型、套餐、设备、设置等）保存为一份带修订号的加密文档：

- `GET /api/v1/state`：读取当前文档；带 `revision` 参数时，数据未变返回 `unchanged`。
- `PUT /api/v1/state`：提交整份修改，必须携带读取时的修订号。修订号不一致时，服务端尝试按字段合并；无法合并时返回 409。
- `POST /api/v1/commands`：执行结构化业务命令（如 `orders.create`），供 AI、CLI 与外部集成使用。

前端 `src/lib/store.tsx` 每 1.5 秒同步一次，并在 CLI 确认执行后立即同步。团队收支、留存策略等独立模块保存在 `studio_modules` 表，各自带修订号。

### 3.4 数据库与加密

- 未设置 `DATABASE_URL` 时，SQLite 文件位于 `STUDIO_DATA_DIR`；设置后使用 PostgreSQL。两种模式都需要持久的 `STUDIO_DATA_DIR`，用于保存留存日志与恢复记录。
- 主要数据表：`workspaces`、`users`、`sessions`、`invitations`、`api_keys`、`business_state`、`state_history`、`studio_modules`、`providers`、`conversations`、`audit`、`rate_limits`、`idempotency`、`leases`、`privacy_files`、`privacy_deletions`、`software_elevations`、`elevations`、`hardware_cards`、`hardware_challenges`、`ai_prefix_usage`、`schema_versions`。
- 业务文档、AI 服务凭据与对话等使用 AES-256-GCM 加密，密钥由 `STUDIO_MASTER_KEY` 派生，并按用途绑定上下文。密码使用慢哈希保存。
- 丢失 `STUDIO_MASTER_KEY` 后无法读取已加密的数据。

## 4. 环境变量

| 变量 | 说明 |
| --- | --- |
| `STUDIO_MASTER_KEY` | 32 字节随机值的 Base64 编码 |
| `STUDIO_ORIGINS` | 允许访问的来源，逗号分隔，例如 `http://localhost:3000` |
| `STUDIO_SETUP_TOKEN` | 服务器部署首次创建工作室时使用的一次性令牌 |
| `DATABASE_URL`、`STUDIO_DB_TLS` | PostgreSQL 连接串及是否启用 TLS |
| `STUDIO_DATA_DIR` | 数据目录 |
| `STUDIO_API_HOST`、`STUDIO_API_PORT`、`STUDIO_API_ORIGIN` | 独立 API 的监听地址与对外来源 |
| `NEXT_PUBLIC_API_BASE_URL` | 前端构建时使用的独立 API 地址；为空表示同源 |
| `STUDIO_AI_ALLOWED_HOSTS` | 允许访问私网地址的自托管模型主机，逗号分隔 |
| `STUDIO_SPEECH_RUNTIME` | 语音识别运行时目录（含 `worker.cjs` 与 `node_modules`） |
| `STUDIO_SPEECH_MODELS` | 软件内安装的识别模型目录；运行时目录下没有 `models/` 时使用 |
| `STUDIO_TTS_RESOURCES`、`STUDIO_TTS_HOME` | 语音合成资源目录与安装目录 |

示例值见根目录与 `cloud/` 下的 `.env.example`。不要提交实际的环境文件。

## 5. 账户、角色与权限

首位账户（UID 0）是超级管理员。之后的成员通过邀请代码注册，邀请时确定角色。

| 角色 | 权限范围 |
| --- | --- |
| `owner` 超级管理员 · 所有者 | 全部，包括成员管理与留存审批 |
| `admin` 管理员 | 除成员管理、留存审批外的全部 |
| `photographer` 受限管理员 · 摄影师 | 查询业务、读取联系方式、编辑订单与工单、查看收支、使用 AI |
| `assistant` 受限管理员 · 业务助理 | 同摄影师 |
| `viewer` 普通用户 · 只读 | 查询业务 |

权限点定义在 `src/lib/permissions.ts`：`business:read`、`contacts:read`、`orders:write`、`orders:delete`、`workflow:write`、`finance:read`、`finance:write`、`settings:write`、`members:manage`、`keys:manage`、`ai:use`、`ai:configure`、`audit:read`、`extensions:execute`、`retention:approve`。

- 浏览器会话使用 HttpOnly Cookie；修改类请求须携带 `X-Studio-CSRF` 头，并校验 Origin。更改成员角色会结束其现有会话。
- API 密钥按服务单独创建，可限定权限点与有效期（1–365 天），随时撤销。密钥加密保存，复制前须验证账户密码。

## 6. AI 助手

- 支持 OpenAI Chat Completions 兼容接口与 Anthropic Messages 接口；预设见 `src/lib/ai-presets.ts`。
- 服务端统一访问模型（`src/server/ai.ts`、`ai-connection.ts`）。默认拒绝私网地址，可用 `STUDIO_AI_ALLOWED_HOSTS` 放行自托管主机。
- 助手可用的工具由“挂载能力”决定（`src/lib/ai-plugins.ts`）：业务查询、业务命令、工作室概况、天气建议、系统诊断、联网检索（Tavily）。助手的权限上限为摄影师，不能管理账户、密钥或款项。
- 写操作只生成方案，用户确认后才执行；取消挂载会撤销未确认的方案。
- 发给模型的工具参数会去掉备注、性别、成年状态等私人字段；联网检索不会发送客户资料。
- 两个化身：男声对应隅鸮 Limenotus，女声对应媱鸮 Limenotessa（`src/lib/assistant-identity.ts`）。

## 7. 语音

语音模型都不需要在构建时打包，可以在软件内安装。

| 能力 | 组件 | 安装方式 |
| --- | --- | --- |
| 语音识别 | sherpa-onnx-node + SenseVoiceSmall INT8 | 运行时 npm 包随安装包分发；模型在助手面板点“安装语音识别”下载，校验后放入 `userData/speech/models` |
| 语音合成 | CosyVoice-300M-SFT，Python 3.11 | 在助手面板点“安装语音”，用随包的 `uv` 安装 Python 与依赖并下载模型 |

- 模型来源、文件名与 SHA-256 记录在 `speech/MODEL.json`、`tts/MODEL.json` 和 `tts/RUNTIME.json`，安装器只接受与清单一致的文件。
- 安装包内已有模型时优先使用；只有部分模型文件时，发布校验判定失败。
- 识别与合成共用一个推理名额，同时只运行一种引擎。

开发环境下准备语音识别：

```powershell
powershell -NoProfile -File scripts/install-speech.ps1          # 安装运行时并下载、校验模型
powershell -NoProfile -File scripts/install-speech.ps1 -OptionalModel   # 只安装运行时
```

## 8. CLI 命令面板

超级管理员在主窗口按 Ctrl + 反引号键打开。语法、模块与命令定义在 `src/lib/cli.ts`，服务端执行在 `src/server/cli.ts`。写入类命令先生成预览，输入大写 `Y` 后在一个事务内执行；执行前核对业务修订号，数据已变化时要求重新预览。完整语法见 [CLI 语法手册](CLI语法手册.md)。

## 9. 资料留存

`src/server/retention.ts` 按交付时间与工作室策略计算保留期，支持延期申请与审批、稍后提醒。清理时先写入删除记录和脱敏的金额快照，再删除客户资料、付款凭证截图及其备份副本。文件加入删除队列时记录大小、修改时间、文件编号与 SHA-256；删除前逐项比对，先将文件原子改名移开并再次核对后才删除，任何一项不一致都会阻止删除并留待人工复核；Git 备份历史中的副本需由超级管理员人工处理后确认。

## 10. 界面语言

- 界面文字用 `useStudioText()` 返回的 `t('中文','English')` 就地编写。
- 服务端返回的提示与系统常量通过 `src/lib/interface-text.ts` 的映射表显示为英文；映射只用于固定文字，用户录入的内容、自定义模板与历史记录保持原文。
- 界面语言与工作室币种分别管理，切换语言不改变金额的币种。

## 13. 构建与发布

```sh
npm run build:api        # 独立 API
npm run build:desktop    # Next standalone 前端
```

`scripts/package-release.ps1` 依次执行：语音运行时准备（模型可选）→ 必跑测试（`npm run check`，含类型检查、错误目录、权限与加密、AI、首次开通、桌面、语音边界、助手与 CLI；以及 `test:team`、`test:retention`、`test:v3-workflow`）→ 构建 → 组装未打包目录 → 打包后运行测试与界面测试 → 生成便携版，并由 `installer/build-installer.ps1` 把未打包目录压缩为数据包、编译安装程序。源码不另行打包，发布页对应版本标签，由代码托管平台自动附带源码压缩包。任一步失败都不会生成安装包。`electron/after-pack.cjs` 调用 `scripts/verify-package.cjs` 校验安装包内容并写入 SHA-256 清单。

## 14. 源码导出

`scripts/package-source.ps1` 导出公开源码快照：先检查公开文档，再复制白名单内的文件，排除依赖、构建缓存、运行数据、模型与内部 QA，最后用 `scripts/audit-public-source.cjs` 扫描私钥、常见 API 密钥格式和本机用户路径。
